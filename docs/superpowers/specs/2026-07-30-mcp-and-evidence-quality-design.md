# MCP 외부 연동과 RAG 근거 품질 고도화 설계

## 1. 목적과 현재 사실

Farmflate는 필지 분석 결과를 바탕으로 사용자가 이해할 수 있는 농업 안내를 제공한다. 현재 사용자 대화의 경로는 `AIChatModal -> Spring AssistantService -> Python GroundedAgent -> PostgreSQL RAG/내부 읽기 전용 도구`이며, 기상은 Spring의 `FieldWeatherService`와 기상청 어댑터가 필지 위치를 기준으로 조회한다.

현재 구현 사실과 목표를 구분한다.

| 구분 | 현재 | 이 설계의 목표 |
| --- | --- | --- |
| Agent 도구 | Python 내부 Function calling, 읽기 전용 | 내부 호출은 유지하고 외부 재사용만 MCP로 제공 |
| RAG 기본 경로 | PostgreSQL lexical FTS | lexical FTS를 기본으로 유지하며 hybrid는 평가 통과 시에만 승격 |
| 벡터 검색 | pgvector/HNSW 준비 및 평가 | 품질·지연 조건을 만족하는 경우에만 운영 후보 |
| 기상 | Spring의 필지 위치 기반 기상청 어댑터 | 동일 도메인 서비스를 재사용하고 별도 날씨 제공자를 추가하지 않음 |
| 외부 웹 정보 | 농사로 수집 경로와 승인 코퍼스 | 임의 웹 검색이 아닌 공식 출처 수집·검증·승인 흐름 강화 |
| MCP | 없음 | Python AI 서버의 선택적 읽기 전용 외부 인터페이스 |

이 작업의 성공 기준은 기능 수가 아니라, 같은 근거를 내부 Agent와 외부 클라이언트가 안전하게 재사용하고 측정 가능한 품질 기준을 통해서만 운영 경로가 바뀌는 것이다.

## 2. 결정과 근거

### 2.1 MCP는 Python AI 서버에 둔다

MCP는 LLM 도구·RAG와 가까운 AI 통합 프로토콜이므로 Python 서버가 담당한다. Spring은 인증, 소유권, 필지·분석·기상이라는 도메인의 원본 조회를 계속 책임진다. 이 결정은 Spring에 MCP와 Agent 오케스트레이션 책임을 섞거나, Python에 기상청 호출·도메인 규칙을 중복 구현하는 것을 막는다.

내부 Agent는 원격 MCP를 사용하지 않는다. 현재 내부 Function calling은 이미 승인된 `FactPackage`와 PostgreSQL 검색 결과만 읽고 있으며, 이를 네트워크 MCP 호출로 바꾸면 요청 홉과 인증 경계만 늘어난다. MCP는 ChatGPT, Codex 또는 별도 서비스가 Farmflate의 읽기 모델을 재사용해야 할 때만 사용한다.

### 2.2 일반 웹 검색은 Agent 도구가 아니다

임의 검색 결과는 출처 신뢰도, 변경 가능성, 프롬프트 인젝션, 인용 검증을 약화한다. 따라서 웹은 수집 단계에서만 사용한다. 수집기는 공식 출처 허용 목록, 원문 지문, 수집 시각, 중복 제거, 파싱 실패를 기록하고 승인된 문서만 PostgreSQL RAG 코퍼스에 반영한다. Agent와 MCP 검색 도구는 승인 코퍼스 밖의 문서를 답변 근거로 사용하지 않는다.

### 2.3 기상은 기존 도메인 서비스를 단일 원본으로 유지한다

`FieldWeatherService`가 필지의 저장된 지역·좌표를 확인하고 `ShortForecastAdapter`가 기상청 응답·캐시·오류를 정규화한다. Python MCP는 이 구현을 복제하지 않는다. 공개 지역 예보가 필요할 때만 Spring의 좁은 읽기 API를 호출한다. 필지별 예보는 사용자 위임 인증과 필지 소유권 검증을 외부 MCP까지 전달할 수 있게 되기 전에는 공개하지 않는다.

## 3. 목표 아키텍처

```text
Farmflate 웹/모바일 ──> Spring
                         ├─ 사용자 인증·소유권 검증
                         ├─ 필지·분석·기상 원본 조회
                         └─ Python에 승인된 FactPackage 전달

Python AI 서버 ──────────> GroundedAgent
                         ├─ 내부 Function calling
                         ├─ PostgreSQL lexical/hybrid 평가 검색
                         └─ 선택적 MCP Streamable HTTP 어댑터
                                  ├─ 승인 농업 지식 검색
                                  └─ 공개 지역 예보 조회 -> Spring 읽기 API

공식 출처 수집기 ────────> 검증·승인·버전 기록 -> PostgreSQL RAG 코퍼스
```

### 3.1 MCP 도구 계약

초기 MCP 서버는 기본 비활성화이며, 명시적 환경 설정과 접근 토큰이 있을 때만 Streamable HTTP로 기동한다. 쓰기, 임의 URL 요청, 임의 SQL, 비밀값 조회 도구는 제공하지 않는다.

| 도구 | 입력 | 반환 | 경계 |
| --- | --- | --- | --- |
| `search_approved_agricultural_knowledge` | `query`, 제한된 `limit` | 짧은 발췌, 출처 제목·URL·문서 지문·수집 시각 | 승인된 PostgreSQL 문서만 검색 |
| `get_public_region_weather` | 정규화된 지역 식별자, 제한된 일수 | 관측/발표 시각, 예보 요약, 제공자 상태 | Spring 기상 읽기 API만 호출, 필지 식별자 금지 |

도구 호출은 입력 길이·열거형·상한을 검증하고, 호출자 식별자·도구명·결과 상태·지연 시간만 기록한다. 질문, 응답 본문, 인증 토큰, 원본 FactPackage는 운영 지표에 저장하지 않는다. 비밀값은 환경 변수 이름만 문서화하고 값은 로그·응답·저장소에 남기지 않는다.

초기 접근 토큰은 통제된 로컬·개발 환경의 서비스 접근 제한용이다. 외부 사용자별 필지 정보를 제공하려면 별도의 OAuth 2.1 사용자 위임, 범위, 철회, 감사 설계가 필요하므로 이 단계의 완료 조건에 포함하지 않는다.

### 3.2 내부 Agent와 MCP의 공통성

Python의 내부 `AgentToolExecutor`와 MCP 핸들러는 같은 읽기 모델과 응답 DTO를 호출한다. 단, 내부 Agent의 `read_authorized_facts`는 이미 Spring에서 검증된 FactPackage를 사용하며 MCP에 노출하지 않는다. 반대로 MCP의 공개 지역 예보는 Spring 도메인 서비스를 경유한다. 공통화 대상은 검색 결과의 출처·상태·시간 정보이며, 사용자 컨텍스트 자체가 아니다.

## 4. RAG 품질과 승격 규칙

### 4.1 평가 데이터와 실행 프로필

평가 실행은 다음 메타데이터를 함께 저장한다.

- 코퍼스 지문, 문서·청크 수, 수집 시각과 승인 상태
- 질의 세트 식별자, 질의 수, 정답 출처 식별자, 생성 방식
- 검색 모드(lexical/hybrid), 모델·임베딩 설정, top-k, 타임아웃, 코드 버전
- 성공·실패 상태, 검색·도구·전체 지연 시간, 인용된 출처 식별자

수치 인용을 위한 Agent 실행 표본은 동일한 모델, 프롬프트 버전, 도구 제한, 타임아웃, 코퍼스에서 최소 30건이어야 한다. 이 표본은 로컬·통제 평가임을 명시하며, 운영 사용자 트래픽 또는 상용 검증이라고 표현하지 않는다.

### 4.2 자동 품질 지표

| 지표 | 계산 | 사용 목적 |
| --- | --- | --- |
| Recall@k | 정답 출처가 상위 k개에 포함된 비율 | 필요한 근거를 찾는지 확인 |
| 인용 정밀도 | 인용 출처 중 정답 근거의 비율 | 그럴듯하지만 무관한 인용 방지 |
| MRR | 첫 정답 근거의 평균 역순위 | 핵심 근거가 앞에 오는지 확인 |
| p50/p95 지연 시간 | 동일 실행 프로필의 분포 | 체감 성능 추정이 아닌 경로 비용 비교 |
| 구조 완료율 | 허용된 종료 상태·섹션·인용 계약을 만족한 비율 | 응답 형식과 근거 연결의 안정성 확인 |
| 도구 실패율 | 도구 상태가 성공이 아닌 비율 | 외부 의존성과 경계 오류 추적 |

자동 평가는 근거 검색·계약 준수의 측정값이다. 사람의 농업적 판단 품질이나 실제 농작물 성과를 증명하는 수치로 사용하지 않는다.

### 4.3 hybrid 승격 게이트

hybrid는 lexical과 동일 코퍼스·질의 세트·top-k에서 비교한다. 최소 사례 수, Recall 향상, 인용 정밀도 하락 없음, p95 지연 시간 비율 상한을 모두 충족할 때만 `RAG_HYBRID_ENABLED`의 운영 후보가 된다. 하나라도 통과하지 못하면 lexical FTS를 기본 경로로 유지한다.

현재 측정에서 hybrid는 지연 증가와 인용 정밀도 하락이 관찰되었으므로 운영 승격 대상이 아니다. 이 문서는 hybrid가 구현되었다는 사실과 운영 기본 경로라는 주장을 명확히 구분한다.

## 5. 실패 처리와 보안

- MCP 도구가 실패하거나 시간 제한을 넘으면 표준 상태 코드와 재시도 권유 없는 안전한 메시지를 반환한다. 내부 원인·비밀값·스택 트레이스는 반환하지 않는다.
- 기상 제공자 빈 응답, 파싱 오류, 캐시 만료, 지역 해석 실패는 기존 Spring 어댑터의 구분된 상태를 보존한다.
- 허용되지 않은 MCP 도구·인자·토큰은 실행 전에 거부한다.
- Agent는 도구가 반환하지 않은 수치·날씨·작업 완료 사실을 생성하지 않으며, 근거가 없으면 `needs_context`로 종료한다.
- 공식 출처 수집 실패는 기존 승인 코퍼스를 삭제하거나 대체하지 않는다. 수집 이력과 실패 원인만 기록한다.

## 6. 구현 순서와 검증

1. Python에 MCP 전송 계층과 엄격한 도구 스키마를 추가한다. MCP 비활성 상태에서 기존 Agent API가 변하지 않는지 검증한다.
2. PostgreSQL RAG 결과를 MCP 공통 응답 DTO로 변환하고, 출처·문서 지문·수집 시각을 보존한다.
3. Spring에 공개 지역 예보용 좁은 읽기 API를 추가한다. 기존 필지별 서비스와 기상청 어댑터를 호출하며, 임의 좌표·필지 ID·쓰기 동작을 받지 않는다.
4. MCP의 토큰 검증, 도구 허용 목록, 입력 제한, 감사 지표를 추가한다. 비밀값은 환경 변수로만 주입한다.
5. MCP `initialize`, `tools/list`, 정상·거부·제공자 실패 `tools/call`을 통합 테스트로 검증한다. 실제 외부 공개나 배포 성공은 이 단계의 주장 범위가 아니다.
6. 고정 평가셋과 실행 프로필 저장을 보완하고, lexical/hybrid 및 Agent 구조 완료율의 30건 이상 측정을 자동화한다.
7. 결과 문서에 측정 조건·표본 수·실패 건수·미통과 게이트를 함께 기록한다. 통과하지 않은 지표는 포트폴리오 수치로 사용하지 않는다.

## 7. 비목표와 포트폴리오 표현 경계

이 설계는 외부 MCP 서비스의 상용 운영, 사용자 위임 OAuth, 필지 데이터의 외부 공개, 일반 인터넷 검색 기반 답변, 자동 hybrid 운영 승격을 이번 범위에 포함하지 않는다.

구현과 통제 평가가 끝난 뒤에는 다음처럼 표현한다.

- 가능: “PostgreSQL FTS 기반 RAG와 읽기 전용 Function calling을 구현하고, 동일 코퍼스·고정 질의셋에서 hybrid 승격 게이트를 검증했다.”
- MCP 완료 후 가능: “외부 AI 클라이언트 재사용을 위해 읽기 전용 MCP 도구를 설계·구현하고, 도구 스키마·접근 제한·통합 계약을 검증했다.”
- 금지: “MCP 기반 Agent 구현”이라고 내부 Function calling만을 지칭하는 표현
- 금지: “hybrid RAG를 운영에 적용”이라고 평가 단계의 기능을 지칭하는 표현
- 금지: 30건 이상 동일 조건의 측정 결과 없이 응답 속도·완료율 개선 수치를 제시하는 표현
- 금지: 로컬·통제 평가 결과를 상용 서비스 검증이라고 표현하는 것
