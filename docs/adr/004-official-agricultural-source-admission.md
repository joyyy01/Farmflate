# ADR-004: 농업 RAG는 출처별 공식 API를 우선하고 범용 크롤링을 금지한다

## 맥락

Farmflate의 Agent는 밭 상태·작물·위험 정보를 설명한다. 일반 웹 검색 결과를 그대로 적재하면 발행 주체, 갱신 시점, 이용 조건, 지역·작물 범위가 불명확해 인용 가능한 조언을 만들 수 없다.

## 조사 결과

- 농촌진흥청 농사로 OpenAPI는 농업기술정보를 외부 서비스에서 활용하도록 공개하며, 신청·인증키 발급·서비스별 샘플 절차를 제공한다.
- 주간농사정보는 작물 관리와 병해충 방제요령, 첨부파일을 제공한다. 프로젝트의 밭 위험·작물 관리 화면과 직접 대응한다.
- 해당 서비스 목록에는 공공누리 유형 3이 표기된다. 적재 시 서비스 페이지·발행일·저작권 유형·출처 표기를 함께 보존해야 한다.

## 결정

1. 첫 운영 후보는 농사로 `주간농사정보`로 제한한다. 범용 검색 결과나 블로그는 RAG 자동 적재 대상이 아니다.
2. API 키는 서버 환경변수로만 읽고, 채팅·프론트엔드·검색 추적에 노출하지 않는다.
3. 수집 결과는 기존 `PENDING → APPROVED → ingest` 절차를 반드시 통과한다. 갱신 주기가 빠른 주간 정보는 `source_version`과 발행 기간, `cntntsNo` 기반 `external_id`를 저장한다. 동일 발행물만 supersede하고 서로 다른 주차 문서는 동시에 검색 가능하게 유지한다.
4. 외부 임베딩은 API의 공개 여부와 별개다. `embedding_egress_allowed`의 명시 승인과 사유가 있어야 하며, 그렇지 않으면 PostgreSQL FTS만 사용한다.
5. 평가 세트는 적재된 문서의 실제 청크 ID를 기대 근거로 사용한다. 공개·반출 허용 출처에서는 LLM이 만든 `AUTO_GENERATED` 실버 질의로 회귀를 먼저 감시할 수 있다. 다만 최소 20개의 사람이 검토한 골드 질의가 쌓이기 전에는 품질 향상 수치를 사용자 품질로 주장하거나 hybrid를 승격하지 않는다.

## 대안과 기각 사유

- 범용 웹 크롤링: 기술적으로 간단하지만 갱신·이용 조건·인용 신뢰도를 통제할 수 없어 기각한다.
- Bedrock Knowledge Base/외부 벡터 DB: 관리 기능은 제공하지만 현재 PostgreSQL 소유권·감사 경계와 중복되고, 데이터 이동과 비용 근거가 부족해 기각한다.
- 로컬 임베딩 모델: 반출을 줄일 수 있으나 모델 배포·자원·품질 재검증 책임이 생긴다. 민감 자료 요구가 확인되기 전까지는 도입하지 않는다.

## 후속 검증

농사로 API 서비스별 계약과 이용 조건을 수집 시점에 다시 확인하고, 등록된 실제 문서·질의 세트에서 lexical/hybrid를 비교한다. 이 ADR은 출처 선택 근거이지 성능 개선 수치의 근거가 아니다. 성능 수치는 코퍼스 지문·평가 origin·실행 ID를 포함한 evidence 문서에서만 인용한다.
